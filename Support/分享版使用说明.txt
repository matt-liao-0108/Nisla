Nisla 0.2.56 · 本地测试分享版（原 Island）

系统要求：macOS 14 或更新版本，支持 Apple 芯片和 Intel Mac。

0.2.56 更新（构建号 58）
- Codex 回复框新增模型选择，模型列表来自当前连接服务；下一次发送生效，运行中停止或完成后可切换。
- 新增 Cursor CLI 的 ACP 接入：会话创建／恢复、流式回复、停止、权限确认、问题回答与计划审批；Agent 页可在 Codex 和 Cursor 之间切换。
- 菜单栏 → 关于 Nisla，或设置 → 外观 → 关于 Nisla，可查看当前运行副本的版本号、构建号和路径。

Cursor 使用：按 https://cursor.com/docs/cli/installation 安装支持 ACP 的 Cursor CLI，在终端运行 agent login。进入设置 → Agent → Cursor，配置可执行文件（通常为 ~/.local/bin/agent）、选择项目文件夹并连接。在 Agent 页选择 Cursor 后新建会话。只安装 Cursor 编辑器不足以连接；此功能不能接管编辑器里的现有聊天和任务。工具权限、问题和计划需要你手动确认。恢复历史依赖 CLI 的 session/load 支持。

连接本身不会发送任务。关闭预览或切换 Agent 来源不会停止后台任务；请点击停止并等待服务端确认。Cursor 会话在 Nisla 中最多保留 16 个标识、标题与项目路径，每个会话内存缓存最近 32 条消息。移除本地记录不会删除 Cursor 的会话。断开连接会终止 Nisla 启动的 CLI 子进程，但不能将未确认的任务标记为已成功停止。

已通过应用编译、隔离协议和相关界面检查；本机尚未安装 Cursor CLI，真实账号登录、模型任务和不同 CLI 版本兼容性仍需安装后验证。Codex 模型选择同样只完成编译与模拟协议验证。

同名副本：搜索可能同时展示「应用程序」、开发构建和解压目录中的 Nisla。日常建议从 /Applications/Nisla.app 启动；关于窗口可以确认当前副本位置。更新前先从菜单栏退出旧版，再替换应用。

English: This update adds Codex model selection, Cursor ACP sessions and About Nisla. Install Cursor CLI and run agent login, configure it in Settings → Agent → Cursor, then create a session on the Agent page. Existing Cursor editor chats cannot be taken over. Live authentication and tasks are not yet verified on this machine.

0.2.48 更新（构建号 50）：默认改为悬浮胶囊，与菜单栏及摄像头安全区域保持间距；展开内容和底部导航合并为一个圆角容器。设置 → 外观 → 展示方式可切回贴顶刘海，保留已有功能、数据及深色渐变。修复 Esc 收起后窗口意外停在屏幕中间的问题，增加实际位置校正；真实 Esc 按键、连续按键、展开中途收起及文本预览焦点检查均已通过。点击面板和预览以外区域时关闭预览，未锁定面板同时收起。Codex 对话只读加载本地用户与助手历史，运行中、未连接或会话被占用时仍可查看可读日志；支持加载更早消息、暂停滚动跟随及回到最新消息。悬浮音量/亮度提示采用 340×44 pt 胶囊，不再预留物理刘海头部空白。

此为 Nisla 自己的悬浮交互，尚未接入或验证新款 Mac 的 Apple 原生 Dynamic Island。音乐、音量、亮度保持按需开启；系统已满足需求时可关闭相应功能并隐藏音乐页。

0.2.47 更新（构建号 49）：Codex 日志预览和实时助手回复支持 Markdown 链接、段落、列表、粗体、标题、代码块及表格；代码块可复制，本地文件链接点击后在 Finder 定位。保留原有回复、追加和停止操作。不会自动加载回复里的图片，不展示 Codex 专属的文件变更或 Undo 卡片。修正音乐一行提示被误算成两行的问题，缩小无歌曲时的按钮行并收紧底部留白；长提示仍按实际行数预留空间。

0.2.44 更新：设置窗口固定顶部 Tab（外观、内容、Agent、日历、音乐、快捷键），隐藏不可用的最小化与缩放按钮。Codex 图标从已安装应用中读取指定的结形资源；默认隐藏内部审查及子任务，原始记录和置顶不删除；审查 JSON 显示只读摘要并可展开原文。发送消息后立即显示用户内容、等待/流式回复状态，发送失败保留草稿；本次消息仅在内存保留，不等于完整历史回放。玻璃改用标准系统 Liquid Glass，并使用共享原生容器。

安装与使用
1. 更新前，点击屏幕右上角菜单栏的 Nisla 图标 →“退出 Nisla”，再替换“应用程序”里的 Nisla.app。若找不到图标，打开“活动监视器”，搜索 Nisla 或旧名称 Island，选中对应应用并点停止按钮 →“退出”。不要同时运行两份相同 Bundle ID 的应用；从旧 Island 迁移时正常退出并移走旧 Island.app 后安装 Nisla。本地数据目录和 Bundle ID 未更改，不会因改名自动删除原有内容。“退出旧版”是安装步骤，与 Codex 会话是否被占用是两回事。
2. 应用常驻菜单栏和屏幕边缘，不在 Dock 显示普通主窗口。
3. 默认快捷键：Control+Command+P 添加剪贴板；Control+Command+I 显示/隐藏；Control+Command+N 新建便签。
4. 菜单栏图标中可以打开设置或退出。快捷键可在设置中修改。
5. 默认“自动（检测系统与设备）”：旧系统或无法确认原生岛能力时使用贴顶刘海。也可手动选择“悬浮胶囊”或“贴顶刘海”。手动悬浮与屏幕顶部安全区域留出 8 pt 间距，收起为 36 pt 高胶囊，有活动时自动加宽，点击或悬停展开，底部导航在同一容器内；贴顶模式保留原独立底部导航。材质保留 AppKit 原生透明玻璃与深色渐变；较旧系统、经典黑色或“减少透明度”使用纯黑。不读取或录制屏幕。
6. 展开与收起动画保持各展示模式的顶部锚点。Esc 可收起面板；预览、文本输入法候选及系统对话框可能优先处理一次 Esc。窗口意外偏移后会恢复目标位置。点击外部时关闭预览，未锁定面板同时收起；锁定面板保持展开。开启系统“减少动态效果”时直接切换，不回弹。
7. 贴顶模式的菜单栏避让默认开启：已授予 Nisla 辅助功能权限时，仅在本机读取菜单元素的位置/大小，以约 1 秒间隔检查可用空间。仅在有效位置数据确认相邻图标空间不足时，依次隐藏歌名、只保留刘海本体；空间恢复后还原正常宽度。读取失败、超时、未授权、切换应用等待新数据或无法确定显示器位置时保持正常宽度，不再把未知当成遮挡，此时不能保证自动避让。鼠标在菜单栏移动本身不再触发收窄。不主动弹权限请求，不读取菜单标题、值或日程/文档内容，不保存或上传位置数据，不采集屏幕图像。
8. 菜单栏左右翼避让仅适用于贴顶刘海模式。悬浮模式按显示器自身的可见区域与顶部安全距离定位，不读取其他应用内容，也不覆盖物理刘海。完整多屏、系统菜单栏自动隐藏及其他菜单管理器组合仍需实机验证。
9. 已通过针对性的悬浮布局、真实 Esc 按键与弹窗焦点回归。原贴顶模式“底部透明间距”的既有完整回归仍未全部通过，不宣称全部回归通过；悬浮模式已验证内容和导航处于同一容器。

签名说明
当前安装包仅做本地 ad-hoc 签名，没有 Apple Developer ID 签名或 Apple 公证。
通过网络传输后，macOS 可能阻止首次启动。只有确认来源可信时，才在系统设置“隐私与安全性”中查看并使用系统提供的打开选项。
此包用于熟人测试，不是已公证的正式发布版本。没有提供禁用 Gatekeeper 的脚本。

数据与权限
压缩包不包含开发者的暂存内容、账号、剪贴板历史或登录凭据。
每位用户的数据仍在其本机 ~/Library/Application Support/Island 中独立保存；为兼容旧版，目录名称没有改。
自动剪贴板历史默认关闭；捕获当前选中内容需用户自行授予辅助功能权限。
网页预览会向相应网站请求公开标题和图片。

Codex
普通暂存区无需 Codex。Codex 集成功能需要对方自行安装并登录 Codex。
首次连接：
1. 先在本机 Codex 中创建并使用一个主会话；Nisla 当前用于继续已有会话，不提供新建会话入口。
2. 在设置 → Agent 中检查 CLI 路径，填写可执行的 codex 文件绝对路径，不能只填 Codex.app、ChatGPT.app 或项目文件夹。终端安装用户可运行 command -v codex 查看位置，再用 codex app-server --help 检查支持情况。另一台电脑的路径可能不同。
3. 没有现成共享服务时，选择“独立 CLI 服务（继续已保存会话）”，点击“连接 / 重连”。无需填写 Socket，也不用手动在终端额外启动一份服务。连接本身不会自动发送模型任务。
4. 等待显示“已连接独立 Codex 服务（非桌面共享连接）”，展开刘海 → Codex →“添加会话”，从最近会话选择一个可写的主会话。图钉用于置顶，点击标题打开对话。
5. 输入后点“发送”或按回车；Shift＋回车换行。任务运行时“追加”可补充指令，标题旁“停止”可请求中断。先显示“正在停止…”，收到结束确认才显示“已中断”。失败或确认超时可重试，部分回复与草稿保留。
已有共享服务：选择“现有本地服务（共享活动）”。CLI 必须支持共享代理，且实际控制 Socket 正在监听；默认 Socket 留空，自定义服务填写真实 Socket 路径，不能填应用路径或创建空文件代替。仅打开 Codex 应用不保证共享服务可用。连接失败时可手动点击“使用独立服务连接”，不会自动切换。
提示会话被占用：表示有 Codex 或其他进程正在写入该会话，不是 Nisla 版本旧，也不是缺少辅助功能权限。如果原窗口还要用这个会话，可点“在 Codex 中继续”或选择另一个可写会话。想转到 Nisla 时，先在原窗口保存并完成/停止任务，关闭对应 Codex 窗口或正常退出占用它的 CLI/应用，再到 Nisla 点“重新检查会话”。停止任务不一定马上释放写入者；切换独立模式也不能绕过占用。不要删除锁文件或会话日志来强行解除。
仅显示活动波形不代表连接成功或可回复；未连接时仍可读取本地日志。内部审查与子任务为只读，可以打开已知主会话。
独立服务不能接管或停止其他窗口正在执行的任务与审批。“断开”不等于停止其他进程的任务。对话区只读加载本地日志中的用户与助手消息，首批最近 24 条，可逐批加载更早消息，最多显示最近 200 条。运行中、未连接或被占用时也可查看可读日志，不需要恢复或抢占会话；向上滚动暂停自动跟随，点“回到最新消息”恢复。工具输出、内部推理和环境注入内容不作为聊天消息显示；日志缺失或不可读时只展示已有消息。实时消息另在内存保留：最多 16 个会话、每个最近 32 条，退出 Nisla 后清空缓存；再打开可重新读取 Codex 已保存的日志。不代表完整 Codex 界面回放。
连接与停止逻辑已通过协议模拟和中英文布局检查；真实模型任务中断仍需实机验证。更多操作与排查见项目 README：https://github.com/matt-liao-0108/Nisla#在刘海中使用-codex
真实回复、审批和额度能力依赖目标 Codex 版本，尚未完成全版本端到端兼容性验收。
Claude Code 和 WorkBuddy 双向连接尚未实现。

日历与待办
设置 → 外观 → 功能页显示：可隐藏暂存、Codex、日历、音乐 Tab；至少保留一个。隐藏不删除数据、不撤销授权，也不停止 Agent 任务。隐藏当前页会自动切换，设置重启后保留。天气尚未接入。
0.2.17 将文件／图片／文字接收页由“置顶”更名为“暂存”（原有内容、Tab ID 和快捷键不变）。拖到刘海时先切到暂存区再展开；取消拖拽或本次收起后恢复此前页面，普通悬停／展开按钮不再自动跳到音乐或 Codex。点击封面或活动图标仍打开对应活动。即使暂存 Tab 被隐藏，拖拽期间也会临时显示，不改动隐藏设置。读取缓慢的文件在面板收起或手动换页后完成时，只保存内容、不抢回页面。Codex 会话的图钉仍叫“置顶”，与暂存内容分开。
0.2.18 增加 AirDrop 投放区：把文件或图片拖到刘海并等待展开，右侧显示 AirDrop；松开后打开 macOS AirDrop 分享界面，由你选择接收设备。多文件一起交给系统；不移动或删除原文件，也不自动选择接收人。暂存区和 AirDrop 分别处理，放入 AirDrop 不会自动保存到暂存区。文本或网页链接仍可拖入暂存区；包含不支持内容的 AirDrop 批次会提示并拒绝，不会悄悄漏发。实际发送依赖设备、系统 AirDrop 和接收方状态。
展开面板 → 日历：左侧查看所选日期起未来 7 天的日程、全天节假日或未完成提醒事项；右侧月历可切换日期并显示日程标记。
日历面板为紧凑布局，背景跟随材质设置。左侧“日程 / 待办”直接切换，顶端可刷新或回到今天；右侧左右箭头直接切换月份，点击日期查看当天起未来 7 天。所有系统来源仍自动读取，未移除任何已授权订阅。
设置 → 日历：分别授权 Calendar / Reminders，自动展示系统可访问的全部日历、订阅和提醒事项列表，无需重复勾选。
需要运行安装后的 Nisla.app 才能弹出正确的权限请求；请勿用 swift run 授权。
系统将所需读取权限称为“完全访问”，但 Nisla 只读、不修改内容，也不向 AI 服务上传日历数据。
节假日依赖系统已有的订阅，不会自动新增节假日或推测调休。
新增或删除系统日历订阅后，Nisla 会重新读取来源；也可手动刷新。日历侧栏临时取消勾选不会从 Nisla 隐藏该订阅。

音乐
播放页在隐藏进度时使用紧凑高度，不为隐藏的进度条预留空白；在来源菜单中切换“显示播放进度”时，面板随之调整高度。无歌曲或权限提示状态仍保留说明文字所需空间。
展开面板 → 音乐；设置 → 音乐中启用并选择播放器，默认关闭。
收起时左侧显示专辑封面和歌名，右侧显示播放状态动画。Codex 活动采用同样排列，左侧读取本机 Codex 图标，右侧显示工作动画；两者同时活动时优先显示当前选中的功能页。隐藏音乐 Tab 或关闭音乐功能后，不再刷新音乐信息。
展开音乐页采用大封面、播放器角标、右侧音柱和横排控制；背景跟随材质设置。左侧列表图标选择播放器并可开启“显示播放进度”；右侧窗口图标打开当前播放器，不代表音频设备切换。中间可切换随机播放、上一首、播放/暂停、下一首（取决于播放器支持）。真实系统音量移到列表菜单中，设备不提供时不显示；不会自动改变音量。音柱仅表达运行状态，不录制或分析音频。
Apple Music / Spotify 通过应用脚本接口读取与控制，首次需用户允许自动化权限。
网易云音乐 / QQ 音乐通过内置 MediaRemote Adapter 读取系统“正在播放”；无需安装 Homebrew 或额外工具。请先在播放器中播放歌曲，并确认 macOS 控制中心的“正在播放”能显示它。
此通道只能跟随系统当前播放来源，不能强行切换后台播放器。选定网易云 / QQ 后，其他来源不会冒充它；来源改变时会拒绝旧的控制请求。自动模式优先跟随正在播放的网易云 / QQ，否则回退直接连接的 Apple Music / Spotify。
MediaRemote 为非公开系统接口，未来 macOS 更新可能使其失效；出错后停止自动重试，可点击刷新手动重试。不会注入播放器、不读取账号或音乐缓存、不调用第三方歌词服务，也不自动播放或切歌。
内置组件来自 https://github.com/ungive/mediaremote-adapter ，BSD-3-Clause 许可位于 Nisla.app/Contents/Resources/MediaRemote/LICENSE。
播放器实际提供封面时才展示。网络封面默认开启，会请求播放器提供的 HTTPS 地址，可在设置 → 音乐中关闭；已有的手动关闭选择会保留。
本地歌曲信息不持久保存或上传至 AI 服务。已验证构建与模拟协议；真实播放器的播放控制与具体版本兼容性仍需用户实机确认。

耳机连接提示
耳机连接提示：在设置 → 外观中开启“在刘海显示耳机连接与电量”（默认关闭）；如系统询问，请自行决定是否授权蓝牙访问。首次开启不提示已有连接；之后耳机新连接时先短暂展开，再缩回窄条显示耳机图标和电量环；正在播放且已有封面时，右侧保留独立封面块。约 6 秒恢复原页面，点击提示可提前收起。不主动配对，不更换音频输出，全部本机读取，不发送到网络。
电量来自 macOS；支持对应系统符号的 AirPods 和可识别的蓝牙耳机。左右耳电量不同时环显示较低值，盒电量单独标注。系统没提供电量时仅显示已连接，不显示虚假的 0% 或 100%。仅顶部停靠展示，不关闭系统自己的蓝牙提示。不同耳机型号的真实电量仍需实机验证。
耳机提示采用系统风格弹性展开、图标柔和浮入、电量环扫入与连续收缩；展开和窄条共用图标与电量环，切换时保持连续。系统开启“减少动态效果”后直接呈现，关闭位移和回弹。
0.2.16 修正收缩中名称过暗、100 电量数字被挤成省略号：文字在收窄前退出，紧凑态只保留图标和电量环。改名设备若有左右耳电量，使用通用入耳式图标，不把自定义名称当作品牌型号。AirPods / AirPods Pro / Max 名称仍使用对应图标。

系统音量 / 亮度提示接管
设置 → 外观 → 系统音量与亮度提示：分别启用音量 / 静音与内置屏幕亮度接管，默认关闭。按需点击“授权辅助功能”，由用户在 macOS 中确认；授权后可点击重新检查。
只处理音量、静音、内置屏幕亮度媒体键；按住连调，Option + Shift 微调。Option 单独、Command / Control 组合及其他按键仍交还系统。键盘背光、普通 F1/F2、其他 App 与控制中心直接调节暂不接管。
调整成功时显示图标、百分比和简洁进度条。悬浮模式使用 340×44 pt 胶囊，贴顶模式在刘海头部下方增加 44 pt 提示内容；不再显示玻璃滑块、双端图标和额外加高布局。展开后可直接点击或拖动进度条设置当前音量 / 亮度；拖动期间不自动收回，松开约 1.4 秒后柔和收回并恢复音乐 / Codex 或原展开页面，不改变当前 Tab 和展开偏好。连续按键只更新进度、不反复重播展开。Esc 可关闭提示并收起面板，不关闭后续按键接管。系统“减少动态效果”开启时直接切换。未授权、设备不支持或调节失败时保留系统按键，进度条也不会伪装成调节成功。亮度使用非公开 DisplayServices 接口，仅支持活动内置屏幕；外接屏与不可调音量的 HDMI / 数字设备不强行接管。
功能完全离线，不记录普通键盘输入，不停用 OSDUIHelper 等系统进程、不需要管理员或关闭 SIP；关闭开关、录制快捷键或退出 Nisla 时移除接管。请勿与其他媒体键 / HUD 接管软件同时启用。
已通过模拟输入、提示自动消失与界面检查；真实按键拦截、权限与不同硬件仍需用户实机验证。测试中没有改变真实音量或亮度。应用更新后如权限失效，请在辅助功能中重新添加当前安装的 Nisla.app。
